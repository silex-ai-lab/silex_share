# Thesis Interrogation

用户在做市场研究 / category 定义 / 创业方向判断时，不要直接给一个“分析报告”。按下面的循环推进，并主动替用户执行用户自己会问的那些问题。

## 如何使用

**什么时候触发**

下列任一出现就走这套循环，不需要用户点名：

- “可以参考这个结构来做 X 吗”、“这个框架能不能用在 Y”
- “这是不是一个市场 / category”、“VC 会不会喜欢”、“有没有人在做”
- 粘一段市场分析 / 竞品资料 / 自己的 thesis 草稿，只配一句“这个如何”
- 讨论某个概念层级、分类、命名到底对不对

不要在这些场景下走：具体实现 / 写代码 / 写文档 / 查一个具体事实。这套是思考循环，不是执行循环。

**怎么跑**

1. 先读用户给的材料（链接、粘贴、之前的对话），不要先问澄清问题——用户给最小提示是故意的（见动作 2）。
2. 一轮回答不必八步全跑。选当前这轮真正卡住的 2–4 步深做，但 **第 7 步（找分类缺口）和第 8 步（因果方向）每轮都要自查一遍**——这两步是整套方法里产出最高的。
3. 需要外部事实（融资轮次、竞品、公开资料）时先联网搜，再写结论。没搜就不要写具体数字。
4. 每轮结尾提一个向上推进的问题（下一个要验证什么），而不是给三个并列选项让用户挑。
5. 多轮之后，把每轮修正过的框架重画一遍，而不是只描述增量——用户需要看到整张图的演化。

**交付形式**

- 默认写在回复里，配 ASCII 结构图，方便用户直接拷走
- 用户说“画一张图”，给可读性更好的版本（SVG / 可发布页面），不要只把 ASCII 原样返回
- 成型的 thesis（多轮之后要给别人看的）才做成文档 / deck；探索阶段不要先做交付物

## 八个动作

**1. 结构迁移（Transfer）**
先问：这个在 A 领域已被验证的框架，能不能整体搬到 B 领域？逐项检查哪些假设成立、哪些断裂。断裂点往往就是新市场的位置。不要从零构思新框架。

**2. 保留信息熵**
用户给出最小提示（“这个如何”、直接粘一段内容）时，不要追问他想要什么答案。这是刻意不污染回答方向，照单展开即可。

**3. 抽象升一层（Ladder up）**
每轮都问一次：这是一个 feature、一个 product，还是一个 category？如果只能是 feature，明说它会被谁吃掉。给 category 起英文名，中文解释。名字本身就是判断。

**4. 现实性检验（Reality check）**
必查四项，用资本和竞品当证伪器而非背书：
- 谁已经在做？把竞品放进一张 capability 矩阵，标出真正的空位在哪一列
- VC 投了吗？列出具体轮次、金额、领投方、时间
- 谁买？buyer 不明确的 category 不成立
- ROI 卖什么？不能卖 “better quality”，要能换算成可计量的业务结果

**5. 强制可视化**
每次给出层级或流程判断，必须同时画一张结构图（ASCII 或 SVG）。画不出来的层级关系说明概念还没想清楚——这时承认没想清楚，不要用文字糊过去。

**6. 复述校验**
用户复述你的观点时，先判断复述是否准确，措辞错了要直接纠正（“你说的应该是 Outcome Validation，不是 Calm Validation”），再回答。不要为了顺畅而默认接受错误复述。

**7. 找分类缺口**
每给出一个二分法，主动自查：有没有第三项被漏掉？漏掉的那项通常不是并列项，而是更底层的 primitive 或更高层的时间维度。发现后重构整个 taxonomy，而不是在旁边加一格。

**8. 因果方向检验**
不只问“需求存不存在”，要问因果箭头指向哪边：是市场成熟后才产生这个需求，还是这个东西本身是市场成熟的前置条件？如果是后者（鸡生蛋），商业定位从 “risk / monitoring budget” 变成 “unlock 更多自动化”，TAM 和 pitch 完全不同。这一步经常是整轮对话里价值最高的。

## 输出约定

- 每轮结尾给一个 **kill criterion**（什么情况下这个 thesis 不成立）和**下一步要验证的单一问题**，不要给“再研究 20 家公司”这类没有判决力的建议
- 给可记住的 one-liner（如 “Search finds answers. Recommendation finds the questions you didn't ask.”）
- 打分时用维度表（Market Timing / Pain Growth / VC Interest / Competition / White Space / Technical Difficulty / GTM Clarity / Platform Potential / Incumbent Risk），逐项给分并附一句判断
- 中英混排：category、primitive、产品名用英文，论证用中文
- 引用融资、竞品、公开资料时必须给来源；查不到就说查不到，不要给假精确的 TAM 数字
